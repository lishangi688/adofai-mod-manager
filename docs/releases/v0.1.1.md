# AMM v0.1.1

本次更新接入了资源站中的 AMM 版本和下载信息，调整了在线 Mod 列表的浏览方式，并修复了更新漏检、重复安装和更新状态显示异常的问题。

## 新增与调整

- **AMM 自身更新接入资源站。** 可以通过资源站检查新版本并获取下载，不方便访问 GitHub 时也多了一个选择。同时查询两个来源时，采用较新的版本；版本相同则优先使用资源站。软件会根据安装版或绿色版给出对应的升级建议。
- **在线 Mod 列表支持滚动加载。** 滚动到底部会继续加载后续内容，不再需要手动翻页，底部会显示已加载数量。
- **UMM 环境新增“直接启动”。** 可以直接运行游戏程序，方便测试。原来的“启动游戏”更名为“Steam 启动”，日常游玩建议使用这一方式。两种启动方式都可以加载 Mod。
- 设置中的“同时查询 GitHub”开关也会用于 AMM 自身更新检查，关闭后不再通过 GitHub 检查 AMM 更新。

## 问题修复

### 资源站改名后无法识别更新

修复了 Mod 在资源站上改名后，AMM 无法匹配更新来源的问题。例如，名称中新增游戏版本说明，可能导致旧版显示“没有更新源”。

现在会优先使用安装时记录的对应关系，并在名称匹配时忽略括号说明、空格和部分标点，减少这类漏检。

### 更新后留下同名 Mod

修复了 Mod 文件夹名与内部 ID 不一致时，更新后仍保留旧副本的问题。

更新时会清理相同 ID 的旧目录，并保留原有的 `Settings.xml` 设置文件。“已安装”页面也会提示重复安装及对应的文件夹，方便检查。

### 重复安装时更新状态显示错误

修复了同一个 Mod 存在多个副本时，更新检查结果互相覆盖的问题，避免出现“当前为 v2.4.1，提示可更新到 v2.4.1”等错误显示。

## 升级方式

退出 AMM 后，下载对应的发布文件：

| 版本 | 文件与操作 |
| --- | --- |
| 安装版 | 运行 `ADOFAI-Mod-Manager-Setup-0.1.1.exe`，覆盖安装 |
| 绿色版 | 将 `ADOFAI-Mod-Manager-v0.1.1-win-x64.zip` 解压，覆盖原目录 |

原有设置和收藏会保留。升级前建议备份游戏目录中的 `Mods` 文件夹。
